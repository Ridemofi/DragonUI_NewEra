# Options window: where taint can arise

This module is addon code, so everything it calls runs tainted. The FrameXML version
(`/root/options_ui`) replaced globals, edited `UIPanelWindows` and set scripts on the stock frames.
The addon version does none of that. Each risk below is marked `TAINT:` in the source.

| # | Where | Risk | What we do |
|---|-------|------|------------|
| 1 | Routing (`Window.lua`, `O.Boot`) | Replacing `InterfaceOptionsFrame_OpenToCategory`, the `*_Toggle` functions or the Esc-menu `OnClick` handlers, or editing `UIPanelWindows`, would taint every caller. | None of them is touched. One `HookScript("OnShow")` on each of the 3 stock frames. The stock OnShow still runs first and securely when the player clicks. It then `HideUIPanel` (the panel manager's own secure delegate, as `modules/social` does) and opens our window. Our window uses `UISpecialFrames` for Esc, not `UIPanelWindows`. |
| 2 | `lastFrame` | The Esc-menu click sets `lastFrame = GameMenuFrame` on the stock frame. The stock `OnHide` would then reopen the menu. | One frame later we read it and write `nil` into that one key. The next secure click rewrites it. |
| 3 | Hosting (`DisplayPanel`, `ReturnPanels`) | `SetParent`, `Show` and a `displayedPanel` write on stock panels and containers. | The panels are plain frames with no protected children. This never happens in combat. On close, every panel goes back to its stock container, so the stock frames are whole again. |
| 4 | Refresh on open | Tainted writes to the controls' `value`/`oldValue` fields. | Refresh calls no `setFunc` and writes no globals. The refresh is skipped for the stock frame whose secure `OnShow` just ran. A stock frame refreshes securely again whenever it is shown itself. |
| 5 | Okay / Apply (`Commit`) | The stock Okay functions call the frame toggles. | They are called with `apply=true`, which skips the toggle. Their handlers only write what changed. Okay in combat is deferred until `PLAYER_REGEN_ENABLED`. Apply in combat prints a message and does nothing. |
| 6 | Cancel / close (`Revert`) | **The real one.** `InterfaceOptionsPanel_Cancel` re-runs every control's `setFunc`. The Action Bars setFuncs write `SHOW_MULTI_ACTIONBAR_*` and move the protected bars. Run from addon code, that taints those globals for the session. In combat it is `ADDON_ACTION_BLOCKED`. | Blizzard Interface panels are cancelled only when they are dirty (some `control.value ~= control.oldValue`). A clean panel's cancel is a no-op anyway. Video/Sound cancels only write the CVars that changed. Close in combat defers the revert until combat ends. **Residual risk:** change an Action Bars box, then Cancel, and the revert runs tainted. A `/reload` clears it. |
| 7 | Defaults | The popup is shown from addon code. Its All/These buttons then run the stock defaults tainted, the same class of risk as #6. | Refused in combat. Same residual risk as #6 for Action Bars. |
| 8 | Combat open | Hosting and handlers are not allowed in combat. | The hook does nothing in combat, so the stock window opens untouched and runs securely. The exception is a window closed in combat whose panels are still hosted. It just shows again, without handlers or reparenting. Tree and search clicks in combat print a message. |
| 9 | Skins (`Skin.lua`) | Changes to stock controls and Esc-menu buttons. | Only texture and font calls and `HookScript`. Our "skinned" marks are kept in a local weak table. `NE.scrollbar`, `NE.buttonskin` and DragonUI's `ForeverUI.SkinButton` write their own private keys, which only they read. No layout or script is changed. The Esc menu's window art is swapped the same way: `SetBackdrop(nil)`, the stock header art and label hidden, and the chrome's new child regions plus its keys (`Bg`, `NineSlice`, `Title`, `_neTitleBand`) on `GameMenuFrame`, which no secure code reads. |
| 10 | Blizzard panel list | The stock `blizzardCategories` is a file local. The FrameXML version exposed it through a LUAXML line. | It is rebuilt from the 17 stock panel globals, keeping only the ones whose OnLoad registered them. Nothing is read through stock internals. |
| 11 | Server FrameXML version still installed | The two versions would fight over the same frames. | If `OptionsUIFrame` exists, the module does not boot and prints one line. |
